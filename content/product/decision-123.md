## Context

[[decision-86]] п. 7 требует open core: опубликованный код остаётся MIT, платные модули Team и Enterprise
пишутся отдельно под коммерческой лицензией, граница проходит по модулям, а не по флагам в клиенте. До
[[TASK-151]] весь репозиторий был под MIT, платных модулей не было. Первыми платными модулями стали бюджеты
([[TASK-145]]) и общий хост ([[TASK-142]]): обе задачи требуют, чтобы их код жил в платной части, поэтому
границу нужно провести до них.

Факты на 2026-10-21:

- Все три сборки идут через Vite: рендерер и main (`vite.config.ts`, `vite-plugin-electron`), ph-agent
  (`vite.ph-agent.config.ts`, [[decision-119]]), мобильный клиент (`mobile/vite.config.ts`). Тесты — vitest
  на тех же плагинах.
- Публичные установщики собирает `release.yml` по тегу и публикует в GitHub Releases.
- Мобильный клиент не содержит логики хоста: всё командное приходит с ПК по RPC Remote Control.

Как это делают другие (по открытой документации и репозиториям):

| Проект | Где платный код | Лицензия | Как отключается |
|---|---|---|---|
| GitLab | каталог `ee/` в том же репозитории | GitLab EE License: исходники открыты, в проде нужна подписка | открытая сборка FOSS без `ee/`, в EE — проверка ключа лицензии во время работы |
| PostHog | каталог `ee/` | своя лицензия для `ee/` | зеркало `posthog-foss` с вырезанным `ee/` |
| Cal.com | `packages/features/ee` | коммерческая | код есть всегда, функции требуют ключ |
| n8n | файлы `*.ee.*` по всему дереву | n8n Enterprise License, остальное — Sustainable Use | ключ лицензии во время работы |
| Mattermost | раньше — отдельный закрытый репозиторий `enterprise` | закрытая | сборка без репозитория |

Рассмотрено и отвергнуто:

1. **Отдельный приватный репозиторий, подключаемый пакетом.** Каждое изменение точки расширения — два
   репозитория, две версии, синхронный релиз. Типы и тесты расходятся. Для одного разработчика и агентов это
   двойная стоимость любой правки. Mattermost в итоге перенёс enterprise-код в основной репозиторий.
2. **Файлы `*.ee.*` по всему дереву, как у n8n.** Граница размыта: платный код лежит рядом с открытым, его
   легко случайно импортировать из открытого файла, и открытую сборку тогда не собрать.
3. **Флаг и ключ лицензии в клиенте, как у GitLab EE и Cal.com.** Прямо запрещено [[decision-86]] п. 7.
   Проверку ключа в открытом коде к тому же можно просто вырезать.
4. **Закрытая лицензия без исходников.** Командам, которым ставят хост в свой контур, нужен аудит кода хоста;
   source-available закрывает это без NDA.

## Decision

1. **Платный код — каталог `ee/` в этом репозитории.** `ee/electron/<модуль>/index.ts` — модули main-процесса
   и ph-agent, `ee/src/<модуль>/index.tsx` — модули рендерера, `ee/tests/` — их тесты. Мобильный клиент
   платных модулей не имеет: командные данные приходят с хоста по RPC и показываются открытым кодом.
2. **Лицензия `ee/LICENSE` — ProjectHub Enterprise Edition License, source-available** по образцу GitLab EE:
   читать, менять и тестировать можно, в проде нужна подписка Team или Enterprise на число участников,
   распространять нельзя. Текст на английском — продукт для мирового рынка. Всё вне `ee/` остаётся MIT.
3. **Открытый код не импортирует `ee/`.** Он читает виртуальный модуль `virtual:projecthub-edition/main` или
   `virtual:projecthub-edition/renderer`. Плагин `scripts/vite-edition.mjs` подставляет туда модули из `ee/`, а
   если каталога нет или `PROJECTHUB_EDITION=open` — пустой список. Проверок «куплено или нет» в клиенте нет.
4. **Точки расширения — в открытом коде, MIT.** Реестр `electron/extensions/editionRegistry.ts`: модуль `ee/`
   экспортирует `register(api)` и подписывается на точки. Первые точки появились вместе с бюджетами
   ([[decision-124]]): проверка перед запуском агента, итог запуска с расходом, методы RPC Remote Control,
   разделы настроек рендерера. Точка — общее понятие открытого клиента («ограничение запуска», «раздел
   настроек»), а не «бюджеты»: открытая версия просто не получает ни одной подписки.
5. **Две сборки.** По умолчанию (разработка, `pack:win`, `ci.yml`) — с `ee/`. Публичный релиз `release.yml`
   собирает открытую редакцию (`PROJECTHUB_EDITION=open`), а `ci.yml` дополнительно проверяет, что открытая
   сборка проходит `tsc` и `vite build` без `ee/`. Сборку Team заказчики получают отдельно, не через
   GitHub Releases; канал распространения — решение при первых платных пилотах.
6. **Правообладатель** — автор репозитория, как в корневом `LICENSE`. CLA для внешних контрибьюторов открытой
   части выбирает владелец вместе с юрлицом; до него внешние PR в `ee/` не принимаются.

## Consequences

- Открытая сборка собирается и работает без `ee/`; платные возможности — отдельный код, а не выключатели.
- Исходники `ee/` видны в публичном репозитории. Это осознанно: защита — лицензия и канал распространения, а не
  сокрытие. *Уточнено в [[decision-158]]:* публичное зеркало собирается без `ee/`, исходники платных модулей
  получают заказчики вместе с Team-сборкой.
- Платный модуль может импортировать открытый код, но не наоборот. Нарушение ловит сборка `PROJECTHUB_EDITION=open`
  в CI.
- Долг: CLA и юрлицо — за владельцем; текст лицензии стоит показать юристу до первых продаж. Канал раздачи сборки
  Team заказчикам не выбран.
- Реализация — [[TASK-151]].
