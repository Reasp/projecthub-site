## Задача — единица работы

В ProjectHub агентам дают задачи, а не файлы. Задачи хранятся в формате Backlog.md: один Markdown-файл на задачу в `backlog/tasks/` с заголовком, описанием, статусом, метками, исполнителем и **критериями приёмки**. Документы и архитектурные решения лежат рядом, в `backlog/docs/` и `backlog/decisions/`.

Задачи — обычные файлы в репозитории, поэтому они переходят вместе с Git, а агенты читают и обновляют их через [MCP-сервер](/ru/docs/mcp/).

Вкладка **Задачи & Backlog** показывает их Kanban-доской или списком. Статусы по умолчанию:

| Статус | Значение |
|---|---|
| To Do | Работа не начата |
| In Progress | Над задачей работает человек или агент |
| Review | Работа закончена и ждёт проверки |
| Done | Принято |

Ещё два статуса передают задачу человеку: **Ждёт человека** (InProgress(Human)), когда работу может разблокировать только человек, и **Проверка человеком** (Review(Human)), когда результат нельзя проверить автоматически. Набор статусов задаёт `backlog/config.yml` проекта.

У задач, которые завёл агент, на карточке есть пометка. Пока вы их не подтвердите, они не запускаются автоматически.

## Worktree на агента

Каждый агент работает в своём Git worktree — отдельной рабочей папке того же репозитория со своей веткой.

- Worktree лежат в `.worktrees/`, имя папки получается из имени ветки. Worktree, созданный из карточки задачи, получает ветку `task/<id>` и папку `.worktrees/task-<id>`. Цикл «До готовности» и Swarm Arena создают свои ветки `swarm/<сессия>/…`. ProjectHub добавляет `.worktrees/` в `.gitignore`.
- Терминалы, процессы и агент worktree работают в этой папке.
- Когда агент заканчивает, ProjectHub коммитит его изменения в worktree, поэтому результат не теряется.
- Слияние безопасное: ProjectHub проверяет, что основная рабочая копия чистая, а при конфликте отменяет слияние и восстанавливает вашу ветку. Можно принять и отдельные файлы вместо всей ветки или открыть pull request.

Поэтому несколько агентов могут одновременно работать над одним репозиторием, а ваша рабочая копия не меняется до слияния. Worktree управляются в **Репозиторий Git → Git Worktrees**.

## Роли

Роль описывает, как работает агент: движок, модель, разрешённые инструменты, правила одобрения, бюджет и системный промпт. Роли — Markdown-файлы с frontmatter. Глобальные роли принадлежат вашему компьютеру; проектные лежат в `.projecthub/roles/` и переопределяют глобальные с тем же именем.

С ProjectHub поставляются шесть ролей, их можно править и копировать:

| Роль | Назначение |
|---|---|
| `architect` | Спецификация и план, только чтение |
| `implementer` | Пишет код в worktree, запускает команды |
| `reviewer` | Читает и комментирует, без записи |
| `tester` | Запускает тесты; пишет только файлы тестов: `tests/**`, `**/*.test.*`, `**/*.spec.*` |
| `manager` | Заводит задачи как предложения, которые подтверждаете вы; код не пишет и команды не запускает |
| `doc-writer` | Пишет только документацию: `backlog/docs/**` и `backlog/decisions/**` |

Роли редактируются в **Agents Studio → Роли агентов**. Чтобы отдать задачу роли, укажите в поле **Исполнитель** значение `agent:<роль>`, например `agent:implementer`. В федерации из нескольких компьютеров `agent:<роль>@<хост>` отправляет задачу на конкретный компьютер (см. [Remote Control](/ru/docs/remote-control/#несколько-компьютеров)).

## Human-in-the-loop (HITL)

Все агенты, которых запускает ProjectHub, проходят через одну очередь одобрений: Agents Studio, Swarm Arena, цикл «До готовности», назначенные задачи и агенты во встроенном терминале.

- Шаги, разрешённые правилами роли, выполняются без вопроса, например чтение файлов или запуск тестов.
- Остальные шаги становятся запросами: команда, изменение файла, вопрос вам. Агент ждёт ответа.
- Отвечать можно на компьютере (карточка в Agents Studio или **Центр решений**), на сопряжённом телефоне или в Telegram. У каждого запроса свой идентификатор; срабатывает первый ответ, остальные устройства видят «уже решено».
- Запрос, на который никто не ответил, отклоняется по истечении времени ожидания: по умолчанию 24 часа, значение настраивается.
- У запросов есть класс риска: низкий (чтение, тесты), средний (запись в проекте, установка зависимостей, сборка, коммит) и высокий (push, удаление, сеть, секреты, запись вне проекта). Запросы высокого риска одобряются на компьютере или в приложении для Android с подтверждением биометрией.
- Агент не может писать за пределами папки проекта, даже при автоматическом одобрении.

Каждое решение записывается в журнал аудита: кто решил (вы в окне, удалённое устройство, автоматическое правило, истечение времени), что одобрено и чем закончилось. Секреты и содержимое файлов не сохраняются, только пути и хэши. Журнал открывается в **Центр решений → История решений**, с фильтрами и выгрузкой в CSV, JSONL или JSON.

## Swarm Arena

Swarm Arena отправляет одну задачу сразу нескольким агентам, например Claude Code, Codex и API-модели. Каждый агент работает в своём worktree.

- Экран сравнения показывает рядом логи, метрики, стоимость и дифф каждого агента.
- Когда агенты закончили, ProjectHub запускает проверки проекта (lint, test, build и typecheck, если они есть) в каждом worktree и ранжирует результаты. Прохождение проверок обязательно; остальные факторы — критерии приёмки, размер диффа, стоимость и время. Веса показываются рядом с баллом.
- Роль `reviewer` может проверить каждый дифф и добавить свои замечания отдельной колонкой.
- Окончательное решение за вами. **Выбрать (Pick)** сливает выбранную ветку и убирает остальные.

Арена запускается из карточки задачи или из Agents Studio.

## Цикл «До готовности»

Цикл **До готовности** запускает одного агента, пока задача действительно не будет выполнена или не будет достигнут лимит. Каждая итерация:

1. Агент делает ход в своём worktree.
2. ProjectHub коммитит изменения.
3. ProjectHub запускает проверки из `.projecthub.json` или `package.json`.
4. ProjectHub читает отчёт агента и сверяет каждый критерий приёмки.
5. Если проверки упали или критерии не выполнены, агент получает ошибки и пробует снова.

Правила цикла:

- **Критерии приёмки отмечает только ProjectHub.** Критерий засчитывается, только если агент сообщил о нём как о выполненном с конкретным доказательством: файл и строка, тест, команда и её вывод. Если агент сам меняет отметки в файле задачи, ProjectHub откатывает правку.
- **Лимиты.** По умолчанию 5 итераций (1–20) и необязательный бюджет.
- **При успехе** критерии отмечаются в задаче, пишется **Final Summary**, задача переходит в **Review**.
- **При неудаче** задача не меняется, кроме короткой заметки с исходом и причиной.
- **Цикл никогда не ставит Done.** Принять результат решаете вы.

Значения цикла по умолчанию задаются в секции `doneLoop` файла `.projecthub.json`; окно запуска позволяет изменить их на один запуск.
