title: "Первые шаги"
description: "От установки до первой задачи, выполненной агентом, на любом Git-репозитории."
---

Это руководство ведёт от свежей установки до задачи, которую выполнил агент и приняли вы. Подходит любой Git-репозиторий; в файлы сборки ничего не добавляется.

## Перед началом

- ProjectHub установлен ([Установка](/ru/docs/install/)).
- Git установлен.
- Есть хотя бы один агент. Проще всего — Claude Code CLI со входом в ваш аккаунт. Другие агенты и модели добавляются в окне **Подключения**.

## 1. Добавьте репозиторий

1. В **Каталоге проектов** слева нажмите **Добавить папку**.
2. Выберите папку репозитория.

ProjectHub умеет и сам находить проекты: **Настроить пути сканирования** задаёт родительские папки, **Сканировать** ищет в них.

## 2. Инициализируйте проект

ProjectHub хранит задачи и документацию в репозитории, в папке `backlog/`. Если чего-то не хватает, у проекта появляется кнопка **Инициализировать**; её подсказка перечисляет, чего нет.

1. Нажмите **Инициализировать**. Откроется окно **Инициализация проекта**.
2. В блоке **Основа** оставьте отмеченными **Git**, **Задачи**, **Документация** и **Правила агентов**.
3. В блоке **Шаблон** выберите **Без шаблона** (только основа).
4. Откройте **Предпросмотр**. Он показывает действие для каждого файла: создать, дописать, слить, заменить или пропустить. Пока вы не нажмёте **Применить**, ничего не записывается.
5. Нажмите **Применить**, затем **Готово**.

Основа добавляет:

- `backlog/` со статусами задач To Do → In Progress → Review → Done и папками для документов, решений и памяти проекта;
- короткую секцию правил для агентов в `CLAUDE.md`, `AGENTS.md` и `GEMINI.md` (ваш текст в этих файлах остаётся);
- запись MCP-сервера ProjectHub в `.mcp.json`, чтобы агенты могли читать и обновлять задачи.

Коммит сам не делается. Окно показывает команду `git add … && git commit` для записанных файлов; проверьте изменения и закоммитьте их сами.

## 3. Создайте задачу

1. Откройте проект и перейдите на вкладку **Задачи & Backlog**.
2. Нажмите **Новая задача**.
3. Введите заголовок и описание. Для первого запуска возьмите что-нибудь небольшое, например «Добавить в CLI флаг `--version`».
4. В блоке **Критерии приемки (DoD)** добавьте один или несколько конкретных проверяемых критериев, например «`app --version` печатает версию из `package.json`».

Задача сохраняется Markdown-файлом в `backlog/tasks/`.

## 4. Отдайте задачу агенту

Откройте карточку задачи и нажмите **До готовности**. В открывшемся окне:

1. В поле **Исполнитель** выберите агента и модель.
2. Проверьте **Лимит итераций** (1–20 ходов агента, по умолчанию 5) и **Проверки**. Проверки берутся из `.projecthub.json` или из скриптов `package.json`. Если проверок в проекте нет, цикл сверяет только критерии приёмки.
3. Оставьте включённым **Перевести в Review при успехе**.
4. Нажмите **Запустить цикл**.

Агент работает в своём Git worktree, поэтому ваша рабочая копия не меняется. После каждого хода ProjectHub коммитит изменения агента в этом worktree, запускает проверки и сверяет критерии приёмки. Если что-то не прошло, агент получает ошибки и пробует снова. Панель **Цикл «до готовности»** показывает итерацию, фазу и сколько проверок и критериев пройдено.

Другой путь: впишите роль в поле **Исполнитель** карточки задачи, например `agent:implementer`, и нажмите **Запустить агента**. Агент один раз отработает с этой ролью в worktree задачи, без цикла.

## 5. Одобряйте шаги агента

Когда агент хочет выполнить команду или изменить файл, а правила не разрешают это автоматически, он останавливается и спрашивает.

1. Запрос появляется карточкой в Agents Studio и в **Центре решений**. Центр решений открывается значком в строке состояния внизу окна; значок показывает, сколько запросов ждут.
2. Прочитайте команду или путь к файлу.
3. Нажмите **Одобрить один раз**, чтобы разрешить этот шаг, или **Отклонить действие**, чтобы запретить его.

Те же запросы приходят на сопряжённый телефон и в Telegram (см. [Remote Control](/ru/docs/remote-control/)). Срабатывает первый ответ. Запрос, на который никто не ответил, отклоняется по истечении времени ожидания (по умолчанию 24 часа).

## 6. Примите результат

Когда цикл завершается успехом:

- критерии приёмки отмечены в файле задачи, у каждого — доказательство агента;
- в задачу дописан **Final Summary** с проверками, стоимостью, итерациями, веткой и коммитом;
- задача переходит в **Review**.

Изменения агента пока лежат в его ветке. Чтобы принять их:

1. Просмотрите дифф ветки агента в окне сессии цикла.
2. Проверьте, что в основной рабочей копии нет незакоммиченных изменений: закоммитьте их или уберите в stash сами, иначе ProjectHub откажется сливать.
3. Нажмите **Выбрать (Pick)** на карточке агента. ProjectHub сольёт ветку в основную. При конфликте слияние отменяется, а ваша ветка остаётся как была.
4. Переведите задачу в **Done**. Сам цикл никогда не ставит **Done**.

Для задачи, запущенной кнопкой **Запустить агента**, откройте вкладку **Репозиторий Git**, найдите worktree задачи в разделе **Git Worktrees** и нажмите **Завершить / Слияние**. Окно **Завершение задачи и слияние** показывает дифф, сливает ветку и может перевести задачу в Review и удалить worktree после слияния.
