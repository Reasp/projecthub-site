## Context

Сайт ProjectHub — отдельный публичный репозиторий, подключённый сабмодулем к источнику (decision-158 источника,
п. 7). Требования из [[TASK-1]] и правил сайта в `CLAUDE.md`:

- статический вывод, который можно положить на любой хостинг; никакого серверного рендеринга и серверных функций;
- Markdown/MDX для документации (раздел Docs наполняется отдельной задачей);
- базовый язык английский, обязательная русская локализация каждой страницы в той же задаче (decision-159
  источника): маршруты по языкам `/` и `/ru/`, переключатель языка, одинаковый набор страниц в обеих локалях;
- тёмная и светлая темы; каждая страница открывается без JavaScript; внешние скрипты и шрифты — минимум;
- без телеметрии, cookie-баннеров и сторонних трекеров;
- деплой по пушу в `main`, предпросмотр для веток; хостинг настраивает владелец, GitHub Actions в проекте не
  используется (decision-148 источника).

## Decision

1. **Генератор — Astro 7 со Starlight** для раздела Docs. Маркетинговые страницы (Home, Download, Pricing, Compare)
   — свои `.astro`-страницы на общем макете `src/layouts/Site.astro`; документация — коллекция Starlight в
   `src/content/docs/`.
2. **Локализация — встроенный i18n Astro.** `defaultLocale: 'en'`, `locales: ['en', 'ru']`, английский без
   префикса, русский под `/ru/`. Строки интерфейса — только через словари `src/i18n/en.ts` и `src/i18n/ru.ts`
   (английский — источник смысла, русский покрывает те же ключи); захардкоженных пользовательских строк в
   страницах нет. У каждой страницы есть пара в другой локали, переключатель языка ведёт на ту же страницу.
   Starlight использует ту же конфигурацию: `root` — английский, `ru` — русский; документы лежат в
   `src/content/docs/docs/*` и `src/content/docs/ru/docs/*`, маршруты `/docs/…` и `/ru/docs/…`.
3. **Данные — из `content/product/`.** Версия, редакции, языки и ссылки читаются из `content/product/product.json`;
   скриншоты и иконка — импортом из `content/product/assets/` (иконки для favicon копирует `scripts/sync-icons.mjs`
   перед сборкой). Данные загрузок — `public/releases/open/releases.json`, страница Download рендерит его при
   сборке и, пока сборок нет, честно пишет об этом.
4. **Темы и JavaScript.** Свои страницы: тёмная и светлая темы через CSS-переменные и `prefers-color-scheme`,
   без JS; небольшой переключатель темы — только прогрессивное улучшение. Внешних скриптов, шрифтов и
   аналитики нет; системные шрифты.
5. **Хостинг — Cloudflare Pages**, подключённый к репозиторию сайта: сборка `npm run build`, каталог `dist`,
   Node из `.node-version`. Пуш в `main` — продакшн, любая другая ветка — предпросмотр по своему URL.
   Заголовки безопасности — `public/_headers`. Настройку (подключение репозитория, домен) делает владелец по
   инструкции [[doc-2]]; GitHub Pages — запасной вариант без предпросмотра веток.
6. **Структура разделов сайта:** Home, Download, Pricing, Compare, Docs (Install, Quick start, Concepts, Remote
   Control, MCP, Editions, FAQ). Состав разделов Docs задан задачей документации в источнике (TASK-144.3) и
   здесь только каркас.

## Consequences

- Плюсы: один стек на маркетинг и документацию; i18n без плагинов; нулевой JS по умолчанию; хостинг без CI в
  репозитории; предпросмотр веток для ревью текстов.
- Минусы: Starlight-страницы несут свой JS для поиска и переключателей (без него читаются, но без поиска);
  две копии каждой страницы (en и ru) нужно держать синхронными — проверяется критерием приёмки задачи.
- Долг: домен и аккаунт Cloudflare — у владельца (ноябрь 2026); демо-видео и сообщество — заглушки до своих
  задач; `releases.json` — заглушка до задачи загрузок в источнике (TASK-144.4).
- Реализация — [[TASK-1]].
