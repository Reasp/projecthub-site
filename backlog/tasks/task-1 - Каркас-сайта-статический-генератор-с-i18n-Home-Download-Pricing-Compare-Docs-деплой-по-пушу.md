## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
### Исполнитель

Агент в репозитории сайта `projecthub-site`. Зеркало задачи TASK-144.2 источника ProjectHub: там ведётся общий план, здесь — работа над сайтом.

### Почему

Публичное лицо продукта без сайта не существует: воронка Personal идёт с Hacker News, Product Hunt и Reddit на сайт, а не в README. Домен и хостинг владелец заводит в ноябре 2026.

### Цель

- Выбрать статический генератор с поддержкой i18n и зафиксировать ADR в `backlog/decisions/`. Предложение по умолчанию — Astro со встроенным i18n-роутингом и Starlight для документации. Критерии: статический вывод для любого хостинга, Markdown/MDX, маршруты по языкам `/` и `/ru/`, переключатель языка, тёмная и светлая темы, страницы открываются без JavaScript.
- Страницы в обеих локалях: Home (тезис, демо-плейсхолдер, установка одной командой), Download (рендерит `public/releases/open/releases.json`; пока заглушка с версией из `content/product/product.json` и пометкой, что сборки появятся позже), Pricing (Personal бесплатно, Team за место с пометкой «в пилотах», Enterprise по договору — строго по `content/product/doc-12.md`, цифры не выдумывать и не округлять), Compare (Orca, Conductor, Vibe Kanban: таблица есть/нет без оценочных слов, факты только из `decision-86.md` и `doc-12.md`), Docs (каркас разделов Install, Quick start, Concepts, Remote Control, MCP, Editions, FAQ — без содержимого).
- Английский пишется первым, русский — перевод в этой же задаче; одинаковый набор страниц в обеих локалях.
- Деплой по пушу в `main` на статический хостинг (Cloudflare Pages или GitHub Pages — выбор в ADR); предпросмотр для веток. Настройку хостинга делает владелец, агент готовит конфиг и инструкцию.
- Проверка в браузере (Playwright): снимки Home и Pricing в обеих локалях на ширине телефона и десктопа, файлы внутри `.playwright-mcp/`, описание — в задаче.

### Ограничения

- Контент — только из `content/product/` и правил сайта в `CLAUDE.md`; возможностей вне экспорта не описывать.
- Без упоминаний РФ и российских сервисов; без телеметрии, cookie-баннеров и сторонних трекеров; внешние скрипты и шрифты — минимум.
- Коммиты — только по запросу владельца.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
### Что сделано (2026-10-22)

- ADR [[decision-1]]: Astro 6.4 со Starlight 0.40 (Astro 7 требует Node ≥ 22.23.4, у владельца 22.16), локали через встроенный i18n Astro (`/` и `/ru/`), данные из `content/product/`, темы через CSS без JS, хостинг Cloudflare Pages (GitHub Pages — запасной без предпросмотра веток).
- Страницы в обеих локалях: Home (тезис, карточки отличий, плейсхолдер демо + скриншот одобрения с телефона из экспорта, сборка из исходников вместо несуществующей установки одной командой, редакции, честное состояние), Download (рендерит `public/releases/open/releases.json`; заглушка с версией 0.1.18 и перечнем запланированных форматов), Pricing (строго по `content/product/doc-12.md`: Personal бесплатно/MIT, Team $25–40 за место в месяц «в пилотах», Enterprise годовая лицензия по договору «не начато»), Compare (таблица есть/нет для ProjectHub, Orca, Conductor, Vibe Kanban только по фактам из `decision-86.md` и `doc-12.md`, прочерк — нет данных), Docs (Starlight, каркас Install / Quick start / Concepts / Remote Control / MCP / Editions / FAQ в en и ru, без содержимого), страницы 404 в обеих локалях.
- Строки — только словари `src/i18n/en.ts` и `src/i18n/ru.ts` (тип `Dictionary` гарантирует одинаковый набор ключей); макет `src/layouts/Site.astro` с переключателем языка на ту же страницу и `hreflang`; `product.json` даёт версию, цены и ссылки (`src/data/product.ts`).
- Сборка `npm run build`: 25 страниц, sitemap, индекс Pagefind. Иконки для favicon копирует `scripts/sync-icons.mjs` из экспорта (`public/icons/` в .gitignore). `public/_headers` — CSP и заголовки безопасности; `.node-version` = 22.
- Деплой: инструкция для владельца [[doc-2]] (подключение репозитория в Cloudflare Pages, build `npm run build`, out `dist`, production `main`, предпросмотр веток автоматически). Сам хостинг не подключён — это делает владелец после появления репозитория на GitHub.
- Проверка в браузере (playwright-core + системный Chrome, JavaScript выключен, снимки в `.playwright-mcp/`): Home и Pricing в en и ru на 390×844 (телефон) и 1366×900 (десктоп), светлая и тёмная тема главной, плюс Compare, Download (ru) и Docs (ru). Все страницы 200, `lang` совпадает с локалью, горизонтального скролла нет; на телефоне навигация переносится на вторую строку, карточки редакций и цен — в одну колонку; на десктопе карточки в три колонки, таблица сравнения помещается без скролла. Страницы Starlight без JS показываются в тёмной теме (их CSS), поиск и переключатели Starlight требуют JS — текст читается без него. На русских страницах латиницей остались только названия продуктов, команды и код.
- Не сделано: демо-видео (плейсхолдер), сообщество («скоро»), реальные ссылки на сборки — ждут своих задач в источнике.
